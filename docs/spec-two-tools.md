# אפיון שני הכלים: מעצב PDF (כמו iForms) ובונה טפסים (כמו JotForm)

_נכתב 2026-10-13 אחרי סיום שלב 2. מסמך זה משלים את `docs/build-plan.md` ומחליף את הגדרת שלב 2 שבו לצורך ההמשך. ההחלטות כאן סגורות; מה שלא כתוב – שואלים את ישראל._

## 0. סיכום למי שממהר

במערכת כבר יש את שני הכלים, אבל כיום הם **כלי אחד עם שני טאבים**: קודם בונים שדות בבונה, ואחר כך מצמידים אותם ל-PDF. ישראל רוצה שיהיו שני כלים שלמים ונפרדים:

- **כלי A – מעצב PDF.** מעלים PDF קיים (טופס 101, טופס בנק, הסכם), שמים עליו שדות ישירות, ושולחים לחתימה. אין צורך לבנות קודם טופס אינטרנטי.
- **כלי B – בונה טפסים.** בונים טופס אינטרנטי מאפס עם כל סוגי השדות, לוגיקה, עמודים ועיצוב. ה-PDF הוא תוצר (או לא קיים בכלל).

שניהם חולקים את אותו מנוע (`FormDefinition`, ולידציה, שרשרת חתימות, ארכיון), כך שההפרדה היא במוצר ובממשק, לא בתשתית. מה שחסר ברמת הנתונים קטן יחסית (סעיף 3). מה שחסר ברמת הממשק גדול יותר (עורך PDF מלא). ברמת התשתית חסרים שלושה דברים שחייבים להיסגר לפני ייצור: אחסון קבצים ב-Blob, חתימה קריפטוגרפית על ה-PDF הסופי, ותיעוד גישה לפי תקנות הגנת הפרטיות (סעיף 4).

## 1. כלי A – מעצב PDF (iForms-style)

### 1.1 מה המתחרים נותנים

iForms לא מפרסם רשימת שדות. מהאתר, ממסמך ה-API ומדפי החתימה שלו עולה: העלאת PDF/Word, "שדות חובה ושדות חתימה" ו"שדות בהגדרה אישית", מילוי מראש דרך API לפי מזהה שדה, קישור חד-פעמי, נספחים ללא הגבלה, סבבי חתימה טוריים או מקבילים עם דחייה, SMS OTP לפני חתימה, אסמכתא אחרי חתימה, "תיעוד מלא של כל פעולה", ארכיון, שליחה ב-SMS/מייל/קישור ושליחה המונית מאקסל, webhook לכל תבנית, ייצוא לאקסל, סליקה. בטפסי 101 הם מצהירים על אישור רשות המסים.

המוצרים הפתוחים (DocuSeal, Documenso) הם הסטנדרט למה "עורך PDF" צריך לכלול, והם מפרטים:

### 1.2 ההחלטה: שדות "יליד PDF"

כיום חותמת (stamp) חייבת להצביע על שדה שקיים ב-`FormDefinition`. זה נכון לתרחיש "טופס אינטרנטי + PDF", אבל זה לא כלי A. בכלי A המשתמש מצייר שדה **על ה-PDF** והשדה נוצר מתוך זה.

**המימוש (ללא טבלאות חדשות):** ציור שדה על ה-PDF יוצר אוטומטית שדה ב-`FormDefinition` של אותה גרסה, בעמוד מיוחד `pages[0]` עם `id: "pdf"` ו-`settings.pdfOnly: true`, וחותמת שמצביעה עליו. הממלא רואה את השדות האלה **מעל ה-PDF עצמו** (מצב מילוי "על גבי המסמך", כמו iForms), ולא כטופס רגיל. כך:

- הוולידציה, התנאים, `filledBy`, הגרסאות והשרשרת עובדים בלי שינוי.
- ניתן לערבב: טופס שנבנה בכלי B יכול לקבל גם שדות ישירות על ה-PDF.
- ייצוא לפריוריטי ו-JSON זהים.

### 1.3 תוספות למודל הנתונים (`PdfStamp`)

```
kind: "text" | "check" | "signature" | "image" | "initials" | "date_signed" | "stamp_image" | "comb"
comb?: { cells: number; cellWidth?: number }     // תאים לתו. cells=9 לת"ז. הטקסט מיושר לימין (עברית) או לשמאל (ספרות) לפי dir
dateFormat?: "dd/mm/yyyy" | "dd.mm.yyyy" | "ddmmyyyy" | "yyyy-mm-dd"   // לחותמות תאריך ו-date_signed
valign?: "top" | "middle" | "bottom"
bold?: boolean
color?: string            // hex, רק לטקסט על PDF (לא UI)
fontSizeAuto?: boolean    // ברירת מחדל true: כיווץ עד minSize
role?: FillerRole         // עוקף את filledBy של השדה (לחותם ספציפי על חתימה-בכל-עמוד)
tabIndex?: number
group?: string            // לשכפול "בכל העמודים": חותמות עם אותו group מתעדכנות יחד
```

`PdfMapping` מקבל גם: `acroImported?: { fieldName → stampId }` (מקור השדה בייבוא) ו-`flatten: boolean` (ברירת מחדל true: שדות AcroForm מקוריים מושטחים אחרי המילוי כדי שלא יישארו שדות ריקים ניתנים לעריכה).

### 1.4 ייבוא AcroForm

`pdf-lib` יודע לקרוא `doc.getForm().getFields()` עם סוג (text/checkbox/radio/dropdown/signature), שם, ומלבנים לכל widget כולל העמוד. ביבוא:

1. לכל שדה נוצר שדה `pdfOnly` + חותמת במיקום המקורי. טקסט עם `MaxLen` ו-flag comb → `kind: "comb"` עם `cells = MaxLen`.
2. השם המקורי נשמר ב-`acroImported`, כך שבמילוי ניתן גם **למלא את שדה ה-AcroForm עצמו** (`form.getTextField(name).setText`) ואז להשטיח – זה נותן טקסט חד וממוקם מדויק בטפסים ממשלתיים.
3. אם ל-PDF אין AcroForm (רוב הסריקות) – המשתמש מצייר ידנית, כמו היום.

פונקציה טהורה `importAcroForm(bytes) → { fields, stamps }` עם בדיקות על טופס 101 הרשמי (יש לו AcroForm) ועל PDF סרוק.

### 1.5 העורך (UX)

עמודה שמאלית: תמונות ממוזערות של העמודים. מרכז: העמוד עם החותמות, צבע לכל תפקיד חותם (מקרא למעלה). עמודה ימנית: פלטת סוגי חותמות (טקסט, תאים, מספר, תאריך, תאריך חתימה, תיבה, רדיו, רשימה, חתימה, ראשי תיבות, תמונה, חותמת ארגון, שם/מייל/טלפון אוטומטיים, ת"ז, טלפון, בנק, כתובת) ומתחתיה הגדרות החותמת הנבחרת.

פעולות: ציור בגרירה על העמוד (לא רק click-to-place), בחירה מרובה (Shift/מסגרת), העתק/הדבק, מחיקה, Ctrl+Z/Y, יישור (שמאל/ימין/מרכז/פיזור שווה), snap ל-grid של 2pt וקווי עזר לחותמות שכנות, "שכפל לכל העמודים", ניווט מקלדת בין חותמות (Tab לפי tabIndex). מצב "מילוי לבדיקה": ממלאים את הטופס על גבי ה-PDF כמו שהעובד יראה.

### 1.6 מצב מילוי "על גבי המסמך"

דף החתימה (שלב 5) מקבל מצב שני: במקום `FormRenderer` מציגים את עמודי ה-PDF עם שדות קלט מעל החותמות (HTML inputs ממוקמים בקואורדינטות המסך, אותם רכיבים מ-`fields/*`). בנייד: רשימת שדות למטה + הדגשה על ה-PDF. הוולידציה זהה (`validateAnswers`).

### 2.2 לוגיקה

| JotForm | Google Forms | אצלנו | עדיפות |
|---|---|---|---|
| Show/Hide field | ✗ | ✓ visibleIf (AND/OR) | – |
| Enable/Require field | ✗ | ✓ requiredIf; ✗ enable/disable | צריך: `disabledIf` |
| **Update/Calculate field** | ✗ | ✗ | **חובה** |
| **Skip to / Hide page** | ✓ "go to section" | ✓ page.visibleIf; ✗ skip-to | צריך: `page.nextPage` עם תנאים (רשימת `{if, goTo}`) – שווה ערך ל-Google |
| Change email recipient | ✗ | ✗ | שלב 6 (כלל ניתוב לפי ארגון/מחלקה) |
| Change thank-you page | ✗ | ✗ | נחמד |
| Mask field (דרך תנאי) | ✗ | ✗ | לא נדרש |

**מודל ל-calculated:** `field.formula: string` בביטוי מצומצם (מספרים, +−×÷, סוגריים, `sum()`, `round()`, `age(date)`, `days(a,b)`, `if(cond, a, b)`, הפניה ל-`{fieldId}` ול-`{table.col}` לסכום עמודה). מנוע הערכה טהור משלנו (`src/lib/forms/formula.ts`, פרסר רקורסיבי קטן – **לא** `eval` ולא ספרייה שמריצה JS), עם בדיקות. השדה מחושב בלקוח בזמן אמת ומחושב שוב בשרת ב-`validateAnswers` (הערך של הלקוח מוחלף).

### 2.3 העורך

מה שיש היום (פלטה, קנבס, הגדרות, תנאים, תצוגה מקדימה, JSON, ביטול/שחזור, שמירה אוטומטית, גרסאות) מכסה את JotForm ברמת המבנה. להוסיף: עורך נוסחאות עם בחירת שדות, עורך "דלג לעמוד", הגדרות ארגון (לוגו/צבע), תצוגת נייד/דסקטופ בתצוגה מקדימה, חיפוש שדה, הצגת מספר שדה בקנבס, "העתק שדה מטופס אחר" (ייבוא מטופס קיים).

## 3. מה שני הכלים חולקים (לא משתנה)

`FormDefinition` (עם התוספות: `formula`, `mask`, `hint`, `unique`, `disabledIf`, `page.nextPage`, סוגים `full_name`, `grid`, `section`), `validateAnswers`, `PdfMapping` (עם התוספות של 1.3), `stampPdf`, גרסאות, `filledBy`, ושלב 5 (שרשרת חתימות, token, audit). ההבדל היחיד: תבנית מסומנת `kind: "pdf" | "web" | "both"` (עמודה חדשה ב-`form_templates`) שקובעת איזה עורך נפתח כברירת מחדל ואיזה מצב מילוי מוצג לממלא.

## 4. בדיקת תשתית: מה מתאים ומה חסר

| נושא | מצב | מסקנה |
|---|---|---|
| **Vercel Functions** | 4.5MB לגוף בקשה ותגובה; 300 שניות ברירת מחדל (Hobby ו-Pro), עד 800 ב-Pro; זיכרון 2GB (Hobby) / 4GB (Pro) | מספיק להחתמת PDF ומיזוג (שניות בודדות). **העלאת PDF חייבת לעבור ל-client upload ישיר ל-Blob** – הגבלת 4MB שלנו היא מעקף זמני. גם **הורדת PDF חתום גדול מ-4.5MB** תיכשל דרך function – לשרת מ-Blob ישירות (URL חתום). |

## 5. סדר הבנייה המעודכן (מחליף את "שלב 2.3" ומוסיף 2.4–2.6)

### שלב 2.4 – כלי A, ליבה (חובה) · ~שבוע
1. `PdfStamp`: `comb`, `date_signed`, `initials`, `dateFormat`, `valign`, `bold`, `role`, `group`, `tabIndex` + מימוש ב-`stampPdf` (comb: ציור תו-תו במרכז כל תא; כיוון לפי `resolveDirection`). בדיקות + PNG ב-`ci-previews` של ת"ז בתאים ותאריך בתאים.
2. שדות `pdfOnly`: ציור חותמת חדשה מהפלטה יוצר שדה בעמוד `pdf` + חותמת. פלטת חותמות בעורך PDF.
3. `importAcroForm()` + כפתור "ייבוא שדות מה-PDF" + מילוי AcroForm והשטחה ב-`stampPdf` כשיש `acroImported`.
4. חתימה בהקלדה (גופן כתב-יד עברי עם רישיון OFL, למשל "Gveret Levin" / "Dana Yad") לצד ציור.
5. `templates.kind` ("pdf"/"web"/"both") + שני כפתורי יצירה ברשימת הטפסים: "טופס מ-PDF" / "טופס אינטרנטי".
**תנאי סיום:** ישראל מעלה את טופס 101 הרשמי, מייבא את שדותיו, משלים ידנית, ורואה PDF ממולא נכון כולל ת"ז בתאים.

### שלב 2.5 – כלי A, עורך מלא (צריך) · ~שבוע
תמונות עמודים, ציור בגרירה, בחירה מרובה, העתק/הדבק, יישור, snap, קווי עזר, "שכפל לכל העמודים", צבע לכל תפקיד, Ctrl+Z/Y, מצב מילוי על גבי המסמך (מכין את דף החתימה של שלב 5).

### שלב 2.6 – כלי B, השלמות (חובה+צריך) · ~שבוע
1. `formula` + מנוע נוסחאות טהור + עורך נוסחאות.
2. `page.nextPage` (דלג לעמוד) + `disabledIf` + `mask` + `hint` + `unique`.
3. סוגים: `grid` (טבלה עם סוג תא), `full_name`, `section`; `info_text` עם Markdown מוגבל.
4. שמירת טיוטה והמשך מאוחר יותר (לפי token; נבנה יחד עם שלב 5).
5. הגדרות ארגון: לוגו + צבע ראשי; redirect אחרי שליחה.

### שלב 3 ואילך – ללא שינוי, בתוספת:
- שלב 3: טבלת `access_log`, הצפנת שדות רגישים.
- שלב 5: `@signpdf` ל-PAdES על ה-PDF הסופי; Blob לפני תחילת השלב; rate limiting.
- שלב 6: ספק SMS ל-OTP.
